# Environment lock

Install the repository's locked Node dependencies with `npm ci` at the repository root.
Run `make -C bench lock-check` there to verify the host tools, model settings against
the locked plan, prompt contents, and local Docker images.

P2a fills `images.app` and `images.db` with maps keyed by the variant and database
identifiers it uses. Each entry has `ref` (the locally inspectable image reference)
and `digest` (the local Docker image ID returned by
`docker image inspect --format '{{.Id}}' REF`). Use the same object for
`images.browser` and `images.agent`. Workers should launch by the checked image ID
so a tag change after preflight cannot change the image they run.

P8 writes the output of `bench/tools/lock-check --print-prompt-sha256` to
`promptSha256`. The hash covers `template.md` and `glossary.md` in that order.
For each file SHA-256 receives the UTF-8 file name, a NUL byte, the decimal byte
length, a NUL byte, and the raw file bytes. Practice scenarios are outside the hash.

Launch the P2/P3 runner through `bench/tools/with-lock RUNNER [ARGS...]` or invoke
`bench/tools/lock-check` and require a zero exit status before any run setup.
Unfilled prompt and image pins cause the check to fail.

Run `make -C bench lock-check-test` after installing the Node dependencies
and making `node:22-bookworm-slim` available locally. The test uses temporary
prompt files and the local image for all four fixture roles.
